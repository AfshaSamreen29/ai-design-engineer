# Page structures by product type

Each outline is a starting point. Reorder, merge, or drop sections according to the visitor's doubts. Every section should answer a question.

## Developer tool or library

1. Hero: what it does, install or try command, link to docs.
2. Demonstration: real code or terminal output; before and after.
3. How it works: three to five concrete steps or a diagram.
4. Details: options, supported environments, performance facts you can substantiate.
5. Ecosystem: integrations, license, repository, contribution path.
6. Closing: install again, docs, community link.

## SaaS application

1. Hero: audience, outcome, primary action, real product visual.
2. Problem and approach: the situation the user is in and how the product changes it.
3. Product tour: two or three key workflows shown with real UI.
4. Proof: only genuine evidence (usage the owner supplies, case study, security facts, uptime page).
5. Pricing or plan summary: honest tiers; mark roadmap items as planned.
6. FAQ: objections about data, migration, cancellation, support.
7. Closing action.

## Local or physical business

1. Hero: what and where, hours, primary action (call, book, order).
2. Offering: menu, services, or products with real photos and prices where possible.
3. Practical information: address, map link, parking, accessibility.
4. Story: short, human, specific.
5. Contact: phone, email, form with clear expectations of response time.

## Agency, freelancer, or portfolio

1. Opening statement: what you do and for whom, in plain language.
2. Selected work: two to six projects with outcome, role, and a link or case study.
3. Process or approach: only if it differentiates.
4. Contact: a direct, low-friction way to start a conversation.

## Mobile app

1. Hero: the app in use, one benefit, working store links.
2. Key moments: three screens or interactions tied to benefits.
3. Privacy and permissions: what data is used and why.
4. Support and press: contact and download links.

## Event or launch

1. Hero: what, when, where, primary action (register, notify me).
2. Schedule or details.
3. People or partners: only real, confirmed names.
4. Logistics and FAQ.
5. Closing action with the date repeated.

## Open-source project

1. Hero: purpose, install command, repository link.
2. Quick start with copyable code.
3. Features that map to real documentation pages.
4. Status: stability, versioning, roadmap, license.
5. Community: how to contribute and get help.

## Section checklist

- Does the section answer a real visitor question?
- Does it have proof or a concrete detail?
- Does it hand off to a next step?
- Would removing it hurt the page? If not, remove it.
